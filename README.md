# 디스코드 후원·커뮤니티 봇

## 실행 준비

1. Python 3.10 이상을 설치합니다.
2. Discord Developer Portal에서 애플리케이션과 봇을 만든 뒤 봇 토큰을 발급합니다.
3. Bot 설정에서 **Server Members Intent**와 **Message Content Intent**를 활성화합니다.
4. 봇 초대 URL의 OAuth2 Scope에 **`bot`과 `applications.commands`를 모두 선택**합니다. 메시지 전송/읽기, 임베드, 메시지 관리, 역할 관리, 채널 관리, 멤버 추방/차단, 멤버 타임아웃, 음성 채널 관리 및 멤버 이동 권한도 필요한 기능에 맞게 부여하고, 봇 역할은 관리 대상 역할보다 위에 둡니다. 이미 초대된 봇에 슬래시 명령어가 안 보이면 `applications.commands` Scope를 포함해 다시 초대하세요.
5. 이 폴더에서 PowerShell을 열고 의존성을 설치합니다.

   ```powershell
   py -m pip install -r requirements.txt
   Copy-Item .env.example .env
   ```

6. `.env` 파일을 편집해 `DISCORD_TOKEN`과 닉네임 검사에 사용할 `SERVER_TAG` 문구를 설정합니다. Discord 공식 서버 태그 장착 여부는 멤버 목록에서 자동 확인하므로 `SERVER_TAG`는 닉네임 문구 검사에만 사용됩니다. 역할·채널·금칙어 값은 기본값으로 사용되며, 봇 실행 후 관리자 명령어로 서버별 변경도 가능합니다. 티켓에 실제 계좌 안내를 표시하려면 `SPONSOR_PAYMENT_INFO`를 로컬 `.env`에만 입력하세요. 토큰과 계좌 정보가 포함된 `.env`는 공유하거나 Git에 올리지 마세요.
7. 봇을 실행합니다.

   ```powershell
   py bot.py
   ```

데이터는 `bot_data.sqlite3`에 저장되어 재시작 후에도 경고와 후원 합계가 유지됩니다. 토큰을 잃어버렸다면 Developer Portal에서 재발급하고 `.env`를 갱신하세요.

## Render 배포

저장소 루트의 [`render.yaml`](./render.yaml)은 Render Worker, 실행 명령, 비밀 토큰 환경 변수와 SQLite 영구 디스크를 설정합니다.

이미 만든 Render Worker를 사용할 때는 이 저장소를 연결하고 **Settings → Build & Deploy**에서 빌드 명령 `pip install -r requirements.txt`, 시작 명령 `python bot.py`를 지정하세요. **Environment**에 Discord Developer Portal에서 발급한 `DISCORD_TOKEN`을 비밀 값으로 추가하고, `BOT_DATABASE`를 `/var/data/bot_data.sqlite3`로 설정하세요. **Disks**에서 1GB 이상의 영구 디스크를 `/var/data`에 연결해야 DB가 재배포 후에도 유지됩니다. 기존 Worker 설정과 동기화할 수 있는 Blueprint라면 `render.yaml`을 사용할 수 있습니다. 이미 Worker를 사용 중이라면 Blueprint가 중복 서비스를 만들지 않도록 주의하세요.

저장소의 `deploy-render.cmd`를 실행하면 `render.yaml`을 GitHub `main` 브랜치에 올리고 Render Worker 페이지를 엽니다. Render에서 자동 배포가 꺼져 있으면 대시보드에서 수동 배포하세요.

`.env`와 `bot_data.sqlite3`는 저장소에 올리지 마세요. 새 영구 디스크는 비어 있으므로 기존 후원 기록을 옮기려면 현재 봇을 중지한 뒤 DB 파일을 별도로 디스크에 복사해야 합니다. Render 계정과 Worker는 별도로 준비해야 합니다. VPS 배포 방법은 [`deploy/README.md`](./deploy/README.md)를 참고하세요.

## 명령어

슬래시 명령어(`/도움말`)와 접두사 명령어(`!도움말`)를 모두 지원합니다. 봇 시작 시 전역 명령어를 동기화하고, 접속된 서버에도 서버 전용 명령어로 복사해 즉시 표시되도록 동기화합니다. 명령어가 계속 보이지 않으면 봇을 재시작하고, 초대 링크에 `applications.commands` Scope가 포함됐는지 확인하세요.

### 서버원 명령어

| 명령어 | 설명 |
|---|---|
| `/도움말`, `!도움말` | 명령어 안내 |
| `/서버원명령어`, `!서버원명령어` | 서버원 전용 명령어 목록 |
| `/후원랭킹`, `!후원랭킹` | 서버별 누적 후원 Top 5 |
| `/코인잔액`, `!코인잔액 [@유저]` | 누적 후원액과 동일한 코인 잔액 조회 (1원 후원 = 1 SNOW) |
| `/유저정보`, `!유저정보 [@유저]` | 가입일, 경고, 후원 및 역할 조회 |

### 관리자 명령어

관리자 전용 목록은 `/관리자명령어` 또는 `!관리자명령어`로 확인합니다.

| 명령어 | 설명 |
|---|---|
| `/티켓패널생성`, `!티켓패널생성` | 후원/문의 패널 생성 |
| `/후원등록`, `!후원등록 @유저 금액` | 후원 금액 수동 등록 및 같은 금액의 코인 적립 |
| `/코인삭제 @유저 수량`, `!코인삭제 @유저 수량` | 코인과 같은 수치의 원화를 해당 멤버 후원 합계에서 차감하고 대시보드 갱신 |
| `/후원차감 @유저 금액`, `!후원차감 @유저 금액` | 입력한 금액만큼 코인과 누적 후원액을 차감하고 대시보드 갱신 |
| `/서버저장`, `!서버저장` | 역할/권한, 카테고리, 지원 채널 구조를 DB에 저장하고 JSON 파일로 내보내기 |
| `/서버복구`, `!서버복구` | 최근 백업을 확인한 다음 버튼 승인으로 구조 복구 |
| `/설화전광판설치`, `!설화전광판설치` | 실시간 후원 대시보드와 티켓 버튼 설치 |
| `/설화목표설정`, `!설화목표설정 금액` | 시즌 목표 금액 설정 |
| `/설화누적설정 @유저 금액`, `!설화누적설정 @유저 금액` | 대시보드 총 누적액을 설정하고 선택한 멤버 후원 기록에 차액 반영 |
| `/후원금액수정 @유저 금액`, `!후원금액수정 @유저 금액` | 멤버의 실제 누적 후원액을 수정하고 TOP 3/대시보드 갱신 |
| `/인증패널배포`, `!인증패널배포` | 신규 유저 인증 버튼 생성 |
| `/설정 보기` 및 `/설정 ...`, `!설정 ...` | 역할, 채널, 금칙어 설정 |
| `/설정 보이스생성방 #채널`, `!설정 보이스생성방 #채널` | 입장 시 2인 숙소 생성 대기 채널 설정 |
| `/설정 잠수방생성방 #채널`, `!설정 잠수방생성방 #채널` | 입장 시 1인 잠수방 생성 대기 채널 설정 |
| `/설정 태그현황채널 #음성채널`, `!설정 태그현황채널 #음성채널` | 공식 서버 태그 또는 닉네임 문구를 가진 인원 수를 채널 이름에 실시간 표시 |
| `/설정 초기화`, `!설정초기화 항목` | 설정을 기본값으로 복원 |
| `/공지생성`, `!공지생성 제목 \| 내용` | 공지 임베드 생성 |
| `/태그목록` | 태그 완료/미착용 전체 명단을 `.txt` 파일로 제공 (닉네임 관리 권한 필요) |
| 티켓의 **후원 금액 승인** 버튼 | 후원 등록 및 승인액과 같은 금액의 코인 지급 |

`/서버저장` 또는 `!서버저장`은 서버 이름, `@everyone` 권한, 서버 역할(권한/색상/표시 순서), 카테고리, 텍스트·음성·스테이지 채널의 기본 설정과 권한 덮어쓰기를 저장하고 JSON 파일을 첨부합니다. JSON은 서버 데이터베이스와 별도로 보관해 두세요. `/서버복구` 또는 `!서버복구`는 해당 서버의 가장 최근 DB 백업을 불러와 확인 버튼을 보여주며, 확인한 뒤 누락된 항목은 만들고 같은 항목은 갱신합니다. 백업에 없는 현재 항목은 삭제하지 않습니다. 봇에 **서버 관리**, **역할 관리**, **채널 관리** 권한을 주고, 봇 역할을 복구 대상 역할보다 위에 두어야 합니다. 역할 순서와 채널 설정은 권한/서버 제한 때문에 일부 복구되지 않을 수 있으며 결과에 실패 항목이 표시됩니다. 메시지, 멤버의 역할 배정, 초대, 이모지/스티커, 밴 목록, 앱/연동 및 지원하지 않는 채널 종류는 포함되지 않습니다. 봇 호스트나 DB를 잃은 경우에도 복구하려면 별도 위치에 보관한 DB 파일이 필요합니다. JSON 첨부는 현재 관리자가 확인/보관할 수 있도록 제공됩니다.

`/태그목록`은 Discord 공식 서버 태그를 이 서버에 공개한 상태인지와 닉네임/사용자명/표시 이름에 `SERVER_TAG` 문구가 포함됐는지를 모두 확인합니다. 둘 중 하나라도 확인되면 태그 완료로 분류하며, 완료/미착용 전체 명단은 `tag_check_result.txt` 파일로 제공합니다. 명단은 채팅 줄글로 출력하지 않으며, 파일에는 각 기준의 확인 결과가 표시됩니다. 공식 태그 이름은 해당 태그를 공개한 서버원 정보를 통해 자동 감지하며, 아무도 태그 정보를 공개하지 않았다면 이름은 확인할 수 없어도 장착 여부 검사는 계속합니다. 태그 DM 발송은 하지 않습니다. 명령어 사용 시 **닉네임 관리** 권한, `discord.py` 2.6 이상, 그리고 Discord Developer Portal의 **Server Members Intent**가 필요합니다.

관리자는 `/설정 태그현황채널 #음성채널` 또는 `!설정 태그현황채널 #음성채널`로 실시간 카운터로 사용할 음성 채널을 지정할 수 있습니다. 채널 이름은 `꒰ঌ✨-ㅣ𝕋𝔸𝔾𝕆ℕ𝔼꒱: 숫자` 형식으로 표시됩니다. 봇 시작 시 전체 인원을 다시 확인하고, 서버원 입장/퇴장 및 닉네임·공식 서버 태그 변경 시 카운트를 갱신합니다. 이벤트로 전달되지 않는 공식 태그 변경은 1초마다 전체 점검으로 보완합니다. 이름이 바뀌지 않은 경우에는 채널 수정 요청을 반복하지 않지만, 실제 변경 요청은 Discord의 채널명 변경 제한에 따라 지연될 수 있습니다. Discord에서 공개 상태가 `None`으로 반환되는 서버 태그도 공개 태그로 셉니다. 카운터가 최신 정보를 표시하려면 봇에 **채널 관리** 권한이 있어야 합니다. Discord의 제한 시간이 길면 봇 실행이나 인원 재확인을 계속하더라도 이름 반영은 지연될 수 있습니다. 해제하려면 `/설정 초기화`에서 **태그 현황 채널**을 선택하거나 `!설정초기화 태그현황채널`을 사용하세요.

`!티켓패널생성` 또는 `/티켓패널생성`으로 새 패널을 생성하면 설화 안내 문구와 **설화 피우기 (티켓 열기)** 버튼이 게시됩니다. 버튼을 누르면 비공개 티켓에 같은 안내와 `SPONSOR_PAYMENT_INFO` 계좌 정보가 자동으로 표시됩니다. 이미 설치된 패널의 버튼 글자까지 바꾸려면 새 패널을 한 번 생성하세요.

후원 티켓 안의 **후원 금액 승인** 버튼은 관리자만 사용할 수 있습니다. 승인 시 후원액이 대시보드와 랭킹에 반영되고, 승인 금액과 같은 양의 `SNOW` 코인이 적립됩니다 (1원 후원 = 1 SNOW). 수동 후원 등록과 누적 후원액 수정도 코인 잔액에 동일하게 반영되며, 봇 시작 시 기존 코인 잔액을 누적 후원 기록과 맞춥니다. 티켓별 중복 승인은 차단됩니다. `!설화전광판설치`로 설치한 패널은 재시작 후에도 저장된 위치를 찾아 갱신하며, 목표 금액은 `!설화목표설정 금액`으로 바꿀 수 있습니다.

관리자는 `/코인삭제 @유저 수량` 또는 `!코인삭제 @유저 수량`으로 코인을 차감할 수 있습니다. 삭제 수량과 같은 숫자만큼 해당 멤버의 누적 후원액도 차감되며, 코인 또는 후원 잔액이 부족하면 변경하지 않습니다. 대시보드가 설치되어 있으면 차감 후 바로 갱신됩니다.

관리자는 `/설화누적설정 @유저 금액`으로 현재 서버 누적 후원액을 지정할 수 있습니다. 차액은 지정한 유저의 후원 기록에 더하거나 빼서 전체 합계를 맞춥니다. 차감액이 해당 유저의 기록보다 크면 처리하지 않으며, 후원 기록이 하나도 없을 때는 먼저 `/후원등록`을 해야 합니다. `/후원금액수정 @유저 금액`은 지정 멤버의 누적 후원 기록 자체를 설정하며 코인 잔액도 해당 후원액에 맞춰 함께 설정합니다. 명예의 전당 TOP 3에는 코인 잔액이 0인 유저는 표시하지 않습니다.

역할/채널은 멘션으로 지정합니다. 예: `!설정 인증역할 @멤버`, `!설정 보이스생성방 #숙소-생성`, `!설정 잠수방생성방 #잠수방-생성`, `!설정 로그채널 #보안-로그`. 두 음성 대기 채널은 서로 다르게 설정해야 합니다. 첫 채널 입장 시 `⌁﹒🏠 . 𝟐인 숙소`(최대 2명), 두 번째 채널 입장 시 `⌁﹒💤 ．𝟏인 잠수방`(최대 1명)을 생성하고 입장자를 이동시킵니다. 생성된 임시 방이 비면 자동 삭제됩니다. 설정은 서버별 SQLite DB에 저장되어 재시작 후에도 유지됩니다. 항목은 `!설정초기화 보이스생성방` 또는 `!설정초기화 잠수방생성방`처럼 이름을 입력해 초기화할 수 있습니다.

인증 역할은 `유저`, `인증대기`가 기본값입니다. 신규 멤버에게 인증 대기 역할을 주고, 10분 내 인증하지 않으면 추방합니다. 음성 생성 채널에 입장하면 임시 음성 채널을 만들고, 비면 삭제합니다. 금칙어 3회는 24시간 타임아웃, 5회는 서버 차단으로 이어집니다. 금칙어는 `!설정 금칙어추가 단어`와 `!설정 금칙어삭제 단어`로 관리할 수 있습니다. 서버 내 모든 채널(음성방 채팅 포함)에서 같은 메시지를 0.3초 간격 이내로 20회 연속 전송하면 24시간 타임아웃을 적용하고 해당 채널에 안내합니다. 도배 타임아웃은 매번 1일로 고정됩니다. 적용하려면 봇에 **멤버 타임아웃(Moderate Members)** 권한을 부여하고 봇 역할을 대상 멤버 역할보다 위에 두세요.
